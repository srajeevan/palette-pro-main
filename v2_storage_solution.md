  Current Problem

  Your Supabase reference-images storage bucket is filling up because:

  1. No cleanup — every image upload creates a new file (userId/timestamp.ext), old images are never deleted
  2. No per-user limits — users can upload unlimited images
  3. Images persist even when palettes are deleted — orphaned images stay in storage
  4. Compression is decent (80% JPEG) but no resizing — large phone photos (12MP+) still produce big files

  Solutions I Can Implement

  Here are the options, from most impactful to least:

  1. Delete old reference images when a user uploads a new one — since only the current working image matters, remove the previous one from storage on each new upload
  2. Delete orphaned images when palettes are deleted — clean up storage when users delete saved palettes
  3. Resize images before upload — cap dimensions (e.g., 1500px max side) since you're extracting colors, not printing photos. This alone could reduce file sizes by 50-80%
  4. Limit stored images per user — e.g., keep only the last N images

  I'd recommend implementing all of 1, 2, and 3 — they complement each other. Want me to go ahead with those three?
